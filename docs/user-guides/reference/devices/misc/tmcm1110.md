# TMCM-1110 fraction collector

Flowchem supports the Analog Devices / TRINAMIC TMCM-1110 StepRocker as a single-axis linear fraction collector over
the USB virtual serial port.

The TMCM-1110 is a close sibling of the [TMCM-1111](tmcm1111.md) and shares the same Flowchem configuration and API
surface. Positions are configured in raw TMCM microsteps, exactly as on the TMCM-1111. Calibrate these values on the
real rail and use names such as `waste`, `vial_1`, or `vial_2` in experiment scripts.

## Configuration

```toml
[device.fraction_collector]
type = "TMCM1110"
port = "COM7"
positions = { waste = 0, vial_1 = 12000, vial_2 = 24000 }
home_position = "waste"
home_on_initialize = false
```

`home_position` is optional. The reference search always zeros `ACTUAL_POSITION` at the calibrated switch location
regardless of this setting (that's a property of the motion controller's own reference-search state machine, not
something Flowchem controls) — so if the position at your switch is already named `0` in `positions` (as in the
example above), you can leave `home_position` unset entirely; `get_position()` will still resolve it to that name.
Set `home_position` only if you want the switch location to map to something other than `0` in your numbering.

The serial connection follows the same pattern as other Flowchem serial devices. `port` is required; the following
serial settings are optional and default to the TMCM-1110 USB serial defaults:

```toml
baudrate = 9600
timeout = 1
bytesize = 8
parity = "N"
stopbits = 1
```

Reference-search and motion settings all have working defaults already — override them explicitly only if your
rail/motor needs different values:

```toml
reference_search_mode = 1
reference_search_speed = 51200
reference_switch_speed = 4096
max_positioning_speed = 51200
max_acceleration = 500000
```

`reference_search_speed`, `reference_switch_speed`, and `max_positioning_speed` are given in microsteps/second
(pps), the same units used for the TMCM-1111; Flowchem converts these to the TMC429 motion controller's
dimensionless velocity units using the pulse divisor currently configured on the device (axis parameter #154).
`max_acceleration` is given in pps² and converted using a *separate* ramp divisor (axis parameter #153) per the
manual's section 6.1.2 ("Acceleration Conversion") — Flowchem reads both divisors from the device and converts
automatically. No manual unit conversion is needed in the TOML file for any of these.

### `PUT /position` not moving the motor

`PUT /position` uses the `MVP` command, which rules its own ramp via axis parameters #4/#5 — entirely separate from
`reference_search_speed`/`reference_switch_speed`, which only apply to `PUT /home`. `max_positioning_speed`/
`max_acceleration` default to `51200`/`500000` precisely because, before that default existed, a board that had
never had #4/#5 set (e.g. right after a power cycle, since axis parameters are volatile SRAM) would report `MVP`
success while producing no motion at all, with homing still working normally. If `PUT /position` still doesn't
move your motor, tune these two values for your rail/motor rather than assuming they're universally safe.

### Where these defaults come from

`TMCM1110.from_config` ships concrete defaults for all five settings above — you don't have to set any of them to
get a working `home()`/`PUT /position`. These are **not** universal constants: they're working example magnitudes
from this project's real-hardware testing, not values measured against a specific TMCM-1110 board and rail the way
the TMCM-1111's are (see [tmcm1111.md](tmcm1111.md)). Treat them as a documented starting point to verify against
your own hardware, not as guaranteed-safe for any TMCM-1110. (The underlying shared driver class still defaults
each of these to "leave this axis parameter untouched" — `TMCM1110` is what layers the concrete values on top.)
`from_config` still accepts a `reverse_shaft` keyword (default `None`) purely so it has the same interface as
`TMCM1111.from_config` (needed for static type-checking of the shared base class), but setting it has no effect
here: axis parameter #251 ("Reverse shaft") doesn't appear in the TMCM-1110's axis parameter table at all.

## API

The `fraction-collector` component provides:

* `PUT /position?position=vial_1`
* `GET /position`
* `GET /available_positions`
* `PUT /home`
* `PUT /stop`
* `GET /limits`
* `GET /target-reached`
